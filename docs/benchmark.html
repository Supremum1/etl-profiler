Методика измерения

CPU — число занятых ядер по изменению счётчика Docker за интервал. Память — Docker working set (usage минус inactive file cache). I/O — байты cgroup block I/O, сеть — счётчики интерфейсов контейнера. В общем столбце памяти суммируются пики компонентов, которые могут происходить в разные моменты. Для метрик без данных показано «—».

Трасса показывает длительность вызовов, включая ожидание. «Чтение» включает получение и декодирование строк, «INSERT» — сериализацию драйвером, передачу и ожидание ClickHouse. В async и hybrid подготовка колонок и ожидание очереди видны отдельно. В параллельном режиме строки дорожек соответствуют PID. Периодический сбор может пропускать короткие пики.

Границы CPU, I/O и сети оцениваются интерполяцией между соседними пробами. Профиль включает накладные расходы наблюдения и фоновую работу контейнеров внутри замера. Подготовка источника, создание и проверка целевой таблицы, удаление таблицы и ресурсы после завершения вставки исключены. PostgreSQL публикует часть счётчиков с задержкой. Чтение вне shared buffers может идти из кеша ОС.

Чтение stream, cursor, keyset и COPY binary сравнивается с разными batch/fetch. Для COPY CSV → HTTP и server-side размеры передачи задаёт сам путь данных. Прогоны выполняются последовательно после прогрева, без принудительного сброса кешей.
